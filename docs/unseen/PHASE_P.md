# Gate P：统一执行器后的受控结果

## 这一轮真正改变的整合

复核发现的核心问题是**动作执行器不统一**：Gate P 用常数动作、闭环用状态机，
名字相同但行为不同。现在三处共用 `scripts/runner.py::EpisodeRunner`：

| 事项 | 旧 | 新 |
| --- | --- | --- |
| 可见量注入 | 预演时没人设 `plan_visible` → `L1/L2` 永远 idle | 执行器统一注入，**L1 触发 270/270** |
| 刹车 | `A0` 设 `brake=True` 但执行器仍 `env.step(a)` → 三次全翻 | 执行器读 `skill.brake` 走 `env.brake_step()`，**150 步刹停、终态 x=−0.003、不翻** |
| 动作身份 | 只有名字 | 记录 `triggered`、`phases`、`action_fingerprint`；**L1 与 R1 指纹交集 0** |
| 场地边界 | 成功可在 x=4.83（地形只到 4） | 执行器判 `out_of_field`；成功记录 0 条越界 |

## 结果（`runs/unseen/gate_p/w6/`，810 回合）

18 正面 × 5 背面 × 3 动作 × 3 初态。障碍 x=1.8，初态 ±0.05 m/±0.03 rad，多凸块碰撞。

| 验收 | 要求 | 本版 |
| --- | --- | --- |
| **P1** 最优选项随背面变化 | ≥4/18 | **4/18 通过**（含 L2 的口径为 6/18） |
| **P2** R1 一背全成功、另一背全失败 | ≥3/18 | **1/18 未通过** |
| **P3** 同正面观测一致 | MAE<2、深度差<2 mm | **未通过**（未重测，最好 3.23） |
| **P4** 30 回合重演 | 必须 | **30/30 一致，通过** |

最优选项确实出现分歧，例如 `s1_h28_w24` 组：cleft→R2、drop→R1、ledge→R1、
ramp_l→R2、ramp_s→R1；`s0_h14_w55` 组：ledge→L1，其余→R1。

## 判读

- **P1 通过**说明"不同背面会让最优走法不同"在这个规模上成立，
  前提是动作真的执行（上一版 2/18 正是因为 L1 从未触发）。
- **P2 仍未通过**：R1 很少"一背全成、另一背全败"，说明当前几何档位还不足以
  让直行在某些背面上彻底失败。
- **P3 仍未通过**：背面未按方案每侧内缩 2 cm，短背面侧缘会露出。
- 按任务书已用两轮物理调整（一是修正实验基础，二是统一执行器）。P2/P3 未过，
  不宣称 Gate P 通过。
