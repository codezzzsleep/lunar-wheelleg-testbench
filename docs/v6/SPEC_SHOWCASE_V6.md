## 0. 方向决定

V5 给出了定量答案：

- 保守机器人把看不见的阴影整片绕开，横向只比知道真值多绕 1.4–7.4 cm；
- 而通过验收的想象，自身误差就有这么大：后缘误差中位数 2 cm，路径高度误差 P95 中位数约 5 cm。

所以在这类场景里，"有想象能做出更好决策"不成立。负责人决定停止追这个结论。

作品改为展示数据里真实成立的东西：

1. **机器人如何想象看不见的那一面**：真实相机图 → 真实 Lux3D 调用 → 原始 3D 模型 → 配准进自己的世界。
2. **只凭看得见的那一面，就能判断哪份想象可信**：C3 中通过验收的 18 份，后缘误差中位数 2.0 cm、路径 P95 49 mm；被拒绝的 29 份分别是 11.7 cm、114 mm。
3. **不可信时如何兜底**：全部拒绝时，可以再看一眼，或回退到"两种极端都安全"的保守做法。按最终规则，有想象的机器人从未比安全做法更差。
4. **轮腿机器人的本领**：平地靠轮子，难处才用腿。
5. **一条连续的月面任务路线**：以上能力在真实执行里依次出现。

## 1. 硬约束

沿用 V5 全部硬约束：密钥只从环境变量读取；Lux3D 每次调用记账；所有动作真实物理执行；动作参数不读真值；N1 先提交脚本再报数；N2 异常自检；N3 场景常数不许写死。新增三条：

- **S1 沙箱不是存储。** 展示用的任何文件（GLB、输入图、相机图、轨迹、预演记录、场景资产）一旦生成，就打包上传到 GitHub Release `v6-showcase`，仓库里只放清单。V5 丢失 GLB 和执行记录的情况不得再发生。
- **S2 可重放。** 每一份轨迹都必须能用素材包里的场景文件和机器人模型原样重放。§4 的重放检查不通过的素材不算交付。
- **S3 不挑数据。** 展示墙和统计用全部样本，不按结果好坏取舍。展示时挑哪几个例子由负责人决定，素材包里必须是全集。

## 2. 工作项

推荐顺序：M0 → M1、M2、M3 并行 → M4 → M5。

### M0 找回并持久化全部 Lux3D 结果

1. 按 ledger 列出所有 Lux3D 任务：
   - v3 生成缓存；
   - WP3 的 144 个任务；
   - V5 C2 的 rock_07 曝光任务。
2. 对每个任务：
   - 用任务号取回结果；
   - 校验 sha256 与 ledger 一致；
   - 连同实际上传的输入图一起保存。
3. 取不回、或 sha 对不上的任务，用 ledger 记录的原输入图重新提交，标 `regenerated_from`，照常记账。
4. 扫描岩石原始资产（`assets/v3/rocks/` 下的网格和贴图）一并上传。
5. 全部上传到 `v6-showcase`。

产出：`dist/v6/lux3d_manifest.json`，每个任务一行，字段如下：

| 字段 | 内容 |
| --- | --- |
| task_id | 任务号 |
| 来源 | v3 / WP3 / C2 |
| rock / view / crop | 岩石、视角、裁剪方式 |
| 模式 | img / imgs |
| 版本、面数 | 生成参数 |
| 时刻 | 提交、完成、取回 |
| 输入图 | 文件名与 sha |
| GLB | sha |
| Release 资产名 | 上传后的名称 |
| 状态 | `recovered` / `regenerated` / `lost` |

### M1 想象体检全集与"自检"统计

1. **补齐 ±25° 两个视角。** 先修好渲染放置（`7d0d3cd5c` 已开始），保证每个视角都有自己的 V/U/真值，且 KA1、KA5、KA6 通过。之后评完 WP3 剩下的 96 份。KA6 修不好就只用 yaw 0，并写根因。
2. **合并 v3 的 75 份候选**（14 个状态，各用自己的真值），形成全集。
3. **自检统计。** 准入只看可见面，用全集检验它能不能分辨好坏想象。
   - "坏想象"的定义写进协议，**看结果之前冻结**：|后缘误差| > 5 cm，或路径 P95 > 80 mm。
   - 需要报告的量：
     - 通过组与拒绝组各自误差的中位数与分布；
     - 准入作为分类器的混淆矩阵；
     - 每个准入指标与真实误差的秩相关；
     - 按岩石分组的结果。
4. 每份候选的展示数据都进素材包，见 §3.3。

产出：

- `runs/v6/m1/checkup_all.csv`
- `runs/v6/m1/selfcheck.json`
- `docs/v6/M1_REPORT.md`

### M2 轮腿本领展示

1. **只有腿能过。** 从 V5 已有的 `rehearsal_3of3.json`（C1、A 线全部组合）里筛出：真值几何下，安全集只含腿式动作（L1、L2、BODY_CLEARANCE），不含任何轮式动作（R1、R2、D1、D2）的组合。
   - 每个这样的组合，在真值里执行两次：WHEEL_ONLY（动作集只含轮式）与 WHEEL_LEG（完整动作集），比较结局。
   - 一个都没有就如实报告，并附上最接近的组合。不得为此新造场景。
2. **轮子优先。** WP7 的六个场景按 §3 的格式重跑并打包。A4（同一段路，轮式 8.82 s，抬身 21.12 s）用来说明平地为什么用轮。

产出：

- `runs/v6/m2/leg_only.csv`
- `docs/v6/M2_REPORT.md`

### M3 连续任务路线

以 WP8 v2 的 20 m 路线为骨架（起点着陆器旁，终点采样点；有碎石区、缓坡、一侧陨石坑），全程一次连续执行。

#### 3.1 遭遇

| 遭遇 | 要展示的 | 选场景的条件 |
| --- | --- | --- |
| E0 碎石 | 小石头不必想象，轮子直接碾过 | 石高低于"想象触发阈值"（见 3.2） |
| E1 想象被采纳 | 想象通过验收，用想象几何规划绕行，贴着石头绕，不绕开整片阴影 | 岩石选 C3 准入率高的（moon_rock_02 或 moon_rock_05）。FULL 决策与 PERFECT 一致且真值通过，优先选轮式绕行。FULL 若选腿式而当时有安全的轮式动作，换场景 |
| E2 全部拒绝 → 再看一眼 | 第一眼的想象全部被拒；机器人横移约 0.4 m 拍第二张；用 `imgs` 多图模式（两张图）重新想象；重新验收后按真实结果走：采纳，或回退到两极端交集的保守动作 | 岩石选 C3 准入为 0 的（moon_rock_01、moon_rock_04、rock_07 之一）。前提是保守动作能安全通过，任务才能继续 |

要求：

- 每个遭遇都现场调用 Lux3D。用机器人当时拍到的图提交：3 种裁剪 × 2 次采样；E2 的第二眼另提交 `imgs` 任务，两张图 × 3 次采样。
- 所有调用照常记账，结果立即上传（S1）。

#### 3.2 现场流水线

1. 到达观测位停车，拍 RGB-D。
2. 判断是否需要想象：石高 ≥ 0.10 m 才触发，阈值写进协议。
3. 调用 Lux3D → 配准 → 准入 → 融合 → 三次扰动预演 → 多数/最坏决策 → 执行。
4. 全程用 V5 的公共评估函数。不许用航点或预设动作代替决策。

#### 3.3 两臂各跑一次全程

- **FULL**：带想象。
- **OBS_CONS**：只看正面，用两极端交集。

两臂同一起点、同一月壤、同一路线。结局如实记录；某臂在某个遭遇停下，就记"停在第几个遭遇"，不改场景。

#### 3.4 失败处理

路线连续执行失败（越界、卡住、翻车），按 V5 的规则：两条修法都失败才停下，并写出根因。

产出：

- `runs/v6/m3/`
- `docs/v6/M3_REPORT.md`

## 3. 素材包格式

### 3.1 通用要求

- 每个包是一个目录，打成 `<unit_id>.tar.gz` 上传。
- 坐标一律为 MuJoCo 世界系、米、z 轴向上。
- 时间一律为仿真秒。

### 3.2 场景与机器人

```
scene/
  scene_spec.json        # 完整场景描述，可直接用于 WheelLegEnv
  heightfield.npy        # 附 heightfield.json：尺寸、分辨率、z 缩放、原点
  rocks/<rock_id>/       # mesh.obj（或 .stl）+ texture.png + pose.json（pos、quat、scale）
  extras/                # 着陆器、采样点等标记（pose.json）
robot/
  model_ref.json         # 所用 go2w MJCF 的来源与 sha；有修改则附修改后的 MJCF
```

### 3.3 想象

```
camera/<look_id>/
  rgb.png  depth.npy  mask.png
  camera.json            # 内参 + 世界位姿 + 拍摄时刻
lux3d/<task_id>/
  task.json              # 模式、版本、面数、提交/完成/取回时刻、状态变化序列；不含密钥
  inputs/                # 实际上传的原图
  tex_mesh.glb           # 原始带贴图模型
candidates/<cand_id>/
  M.json                 # 配准变换
  admission.json         # 五项指标、门槛、判定、原因
  hidden_metrics.json    # 与真值比较的误差，只用于评估
fusion/
  occupancy.npz          # origin、pitch、dims，以及 V、U、U_shadow、每份候选的 P（bit 打包）
decision.json            # 分支（采纳 / 再看一眼 / 全部拒绝→回退）、各候选安全集、多数与最坏的选择、最终动作、原因
```

### 3.4 预演与执行

```
rehearsal/<arm>/<cand_or_geom>/<action>/p{0,1,2}/
  traj.npz               # 全部格子都要，不只关键格
  result.json
runs/<arm>/
  traj.npz
  result.json            # 结局、t_end、接触数、能耗、路程
```

`traj.npz` 的字段：

| 字段 | 内容 |
| --- | --- |
| `t` | 时刻 |
| `qpos`、`qvel` | 机器人状态 |
| `ctrl` | 控制量 |
| `action` | 每步动作名 |
| `phase` | 每步阶段名 |
| `joint_target` | 关节目标 |
| `wheel_speed` | 轮速 |
| `contacts_chassis` | 机身接触数 |
| `contacts_wheel` | 每个轮子的接触 |
| `soil` | 每步所用月壤参数标签 |

采样不低于 50 Hz。

### 3.5 清单

```
manifest.json            # 每个文件的路径、sha256、字节数、生成命令、所用提交
```

## 4. 重放检查

`scripts/v6_replay_check.py <包目录>`，对每个包做三件事：

1. 用 `scene/` 与 `robot/` 重建 MuJoCo 模型，逐帧写入 `traj.npz` 的 qpos 后做 `mj_forward`。
   要求：机器人与岩石、地面的最大穿透 ≤ 5 mm；末帧与 `result.json` 一致。
2. 用 `MUJOCO_GL=egl` 渲染首帧、中间帧、末帧各一张 PNG，存进包内 `check/`。
3. 校验 `manifest.json` 中所有文件的 sha256。

检查结果写 `check/replay_check.json`。不通过的包不上传。

## 6. 立即停下并回报

1. M0 有任务既取不回、也无法用原输入图重新生成。
2. 重放检查对某类素材系统性不通过，例如场景文件与执行时的场景不一致。
3. M3 路线连续执行两条修法后仍失败。
4. N2 异常自检触发且查不出原因。

## 7. 明确不做
