# Gate P：同正面、不同背面（未通过 — 实现缺陷，不是物理否定）

## 做了什么

`scripts/twins.py` 生成"双胞胎"障碍：正面完全相同（确定性带噪半椭球），
背面 5 种（drop / ramp_s 25° / ramp_l 12° / ledge / cleft），
`runs/unseen/gate_p/r1|r2/mesh/` 共 40 个 STL，背面描述量已计算
（背深 0.14–0.57 m、背坡 12°/25° 两档，彼此可区分）。

## 阻塞在哪

**双胞胎网格不是流形**，导致现有处理链把整块几何替换成凸包：

| 构造方式 | 非流形边 | `process_asset` 结果 |
| --- | --- | --- |
| 正面+背面两段拼接 | 36–40 条 | `coacd_parts=1`，`near_convex_hull_substituted=true`，凹度 0 |
| 单一放样实体 | 27–48 条 | 同上 |

凸包替换会把"背面的台阶/横槽"整块填平，因此**两种背面的碰撞几何事实上相同**，
Gate P 的物理见证根本不成立。若在此状态下跑动作矩阵，得到的"无差异"是几何丢失造成的，
不能当作"背面不影响动作"的证据，所以没有跑。

原因已定位到接缝：正面半椭球封口与背面型面封口在 x=0 处重复了边，
手写缝合没有正确合并（`merge_vertices` 默认阈值不足，且底面矩形与曲面共享边被计了三次）。

## 下一步（明确、可执行）

1. 用 `manifold3d` 的布尔并集把正面与背面合成单一实体（本机版本 API 与文档不一致，
   需先核对 `Manifold.to_mesh()` 的字段名），或
2. 直接用 Marching Cubes 对符号距离场重建（需要 `scikit-image`，先验证依赖），
3. 产出后必须本机验证：非流形边 = 0、`coacd_parts ≥ 2` 对于 ledge/cleft、
   且 drop 与 ramp_l 的碰撞体积差 > 5%。

## 结论

Gate P **未通过**，原因是几何构造缺陷，尚未得到任何"背面影响动作"的物理证据。
按任务书第五节，这属于实现缺陷，不能据此宣称任何关于机器人的结论。
