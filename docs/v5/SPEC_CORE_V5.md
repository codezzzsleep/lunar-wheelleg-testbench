## 0. 为什么换打法

### 0.1 核心结论从来没有闭合过

作品要证明的只有一句话：**机器人只看到石头正面时，用 Lux3D 想象出背面，会做出和"只看正面"不同的决定，而且在真值物理里结果更好。**

从 v3 到现在，这条链一次都没跑通：v3 有 14 个配对，FULL 和 OBS 的结局全部相同；V4 的 WP4 差距拿回 0。之前铺开九个工作包并行，容易的外围（WP0/1/6/7）做完了，证明核心的 WP2/3/4/5 全部失败或停在一半。这一版只做一件事：把核心链打通，其他全部暂停。

### 0.2 已确认的测量缺陷（项目负责人复核代码和数据得出）

1. **后缘和顶点量的是可见壳，不是候选。** `scripts/v4_wp3_eval.py` 第 49 行先做 `full = V['shell'] | (候选体素 & U)`，再在 `full` 上取后缘和顶点。结果：5 组里 3 组同组 6 份候选后缘误差完全相同，5 组顶点误差中位数都在 0–2 mm。
2. **参照写死成 moon_rock_05 首视角。** 同一脚本把 `V`、`U`、真值网格固定为 `runs/v3/stage008/truth_v2`，±25° 视角和其他岩石都在拿错的参照比。rock_02/03 的结果来自未入库的脚本，无法复现。**"rock_03 后缘偏短 12.8 cm、触发 §6"作废。**
3. **Lux3D 模型是开口外壳，奇偶射线法把它掏空。** 实测 Release 中一份 moon_rock_05 的 GLB：3 个碎片、非水密，有符号体积只有凸包的 2.6%。用 `v3_fuse.voxelize_columns` 的奇偶配对填实，只填进"地面到顶面"体量的 41–49%。WP3 候选只有 3.5–18.6 万体素，真值 125.6 万。
4. **空地侵入比被放大。** 侵入比的分母是候选自己的体素数，候选被掏空，比例就被放大十几到二十倍。按真值体量粗算，moon_rock_05 首视角两份候选的侵入约 1.6%。2% 门槛是负责人在实心真值上定的，对开口外壳不适用，这是负责人的错误，本版收回。
5. **很可能 v3 的"FULL 与 OBS 结局 14/14 相同"也来自第 3 条。** v3 的隐藏区 IoU 0.011、漏填 98.9%：候选被掏空后，P∩U 几乎为空，FULL 几何约等于 V，决策自然和 OBS 一样。C0 修正后要用 v3 原有候选重做来验证这一点。

### 0.3 保留的事实

- 配准入口可用（真值 IoU 0.96、深度 P95 19.9 mm）；统一终点 `wheelleg_env._task_check` 有效。
- WP6：BODY_CLEARANCE 11.78 s、0 接触。WP7：六个展示场景完成。WP8 v2：20.42 m 连续执行通过。
- Release `v4-data`：172 份 v3 资产可取回。

## 2. 共用定义（本版修订）

### 2.1 占据表示：2.5D 列填实（候选与真值统一）

- 每列从地面填到该列最高交点，不做奇偶配对，不要求网格水密。
- 实现见附件 `column_fill_top`。
- 填实前先丢掉面数少于总数 2% 的孤立碎片。
- 真值、候选、标定用的扰动先验，全部用这一个函数。融合几何 `FULL = V ∪ (P∩U)` 里的 P 也改用它。
- `v3_fuse.voxelize_columns` 不再用于候选。

### 2.2 隐藏区指标：只在未知区内比较

`H_c = P ∩ U`，`H_t = T ∩ U`（z > 0.02 m）。实现见附件 `hidden_metrics`。

| 指标 | 定义 |
| --- | --- |
| `rear_err_m` | H_c 与 H_t 的最大 x 之差，负数表示想象偏短 |
| `top_err_m` | H_c 与 H_t 的最高点之差 |
| `path_mae_mm` / `path_p95_mm` | 机器人车道（\|y\| ≤ 0.20 m）内、未知列上的高度图误差 |

**禁止在 V∪P 上量任何隐藏区指标。**

### 2.3 每个场景用自己的参照

- 每个场景（岩石、视角、尺度、布置）都有自己的观测、V/U、真值，三者在同一世界坐标下。
- 评估脚本从场景目录读取这些，不许出现写死的路径。

### 2.4 候选准入（重新标定）

五条沿用 V4 §2.4：尺度比、与壳相接、空地侵入、轮廓、数据完整。改动如下：

- 所有体积量都按 §2.1 的表示计算。
- 侵入比 = 侵入已知空地的体素 ÷ 候选实心体素。另外记录**侵入深度 P95（mm）**，只报告。
- **门槛只用已知答案标定，看候选之前冻结：**
  - 真值，以及真值平移 ±2 cm、缩放 0.9/1.1，必须通过；
  - 平移 15 cm、缩放 0.6 两个坏对照必须被拒。
- 标定结果写 `configs/v5_admission.json`。`configs/v4_admission.json` 废止。

### 2.5 各臂

`PERFECT`、`FULL`、`OBS_CONS`、`OBS_OPT` 的定义同 V4 §2.1–2.2，OBS_CONS 不变：

- 绕行路径经过未知体素即判不安全；
- BODY 带 `unknown_hold`。

### 2.6 价值的定义（替代"省 30 s"）

| 类型 | 条件 |
| --- | --- |
| **I 类：结局不同** | PERFECT 在真值上 pass，OBS_CONS 是 safe_stop 或 fail |
| **II 类：代价不同** | 两者都 pass，PERFECT 的 `t_end` 比 OBS_CONS 少 ≥30% 且 ≥3 s |

旧的"省 30 s"是在 BODY 要 113 s 时定的，BODY 降到 11.78 s 后不再适用。

### 2.7 决策

- 主规则：多数（≥⌊n/2⌋+1）安全的动作里，选代价最低的。同时用最坏规则（n/n）各选一次；两者不同时，两个都要在真值上执行。
- **轮子优先**：代价相差 <5% 时选纯轮动作（R1/R2/D1/D2）。写进 `configs/v5_protocol.json`。
- 零候选准入：回退 OBS_CONS，记 `fallback_reason`。
- 决策先落盘，再执行。

### C1 价值筛选（只用真值和观测，不调用 Lux3D）

1. 场景来源是 v3 的 48 个状态（8 岩石 × 3 高度 × 2 变体），都是真实岩石、真实背面，已有观测和真值。
   先做 v3 判为"隐藏敏感"的 23 个，再做其余 25 个。
2. 每个状态在统一终点下跑 PERFECT、OBS_CONS、OBS_OPT，按 §2.7 决策，并在真值上执行。
3. 按 §2.6 标出 I 类、II 类价值场景。
   每个场景写一句**为什么**：例如"背面短，右绕能过；OBS 不知道背面长度，绕行路径穿过未知区，只能抬身"。
4. **I 类少于 1 个时，加"窄道"布置再筛一遍。** 布置固定为：
   - 左侧坑沿：落差 ≥0.4 m；
   - 右侧乱石群：石高 ≥0.4 m，不可跨；
   - 绕行侧净宽 = 机器人实测外宽 + {0.15, 0.40} m 两档。
   目的是让"能不能绕过去"只取决于石头背面有多长，观众一眼能看出为什么不绕远路。
5. 价值场景为 0 时停下回报，附每个场景各臂的动作和原因。

产出：

- `runs/v5/c1/value_table.csv`（每场景：各臂动作、结局、t_end、能耗、价值类型、原因）
- `docs/v5/C1_REPORT.md`

### C2 核心闭环（主目标）

在 C1 的价值场景上（I 类优先，最多 6 个）：

1. **候选**：用该状态原有的 v3 Lux3D 候选（来自这个状态自己的观测图）。
   该状态没有候选、或候选少于 3 份时，用该状态的机器人相机图重新调用 Lux3D：3 种裁剪 × 2 次采样 = 6 个任务，模式 `img`，照常记账。
2. **流水线**：配准 → C0 准入 → 融合 FULL 几何 → 预演矩阵 → 按 §2.7 决策 → 在真值上执行。PERFECT、OBS_CONS、OBS_OPT 在同一初态、同一月壤下各执行一次。
3. **完成标准**：至少 1 个场景里，FULL 与 OBS_CONS 的决策不同，且 FULL 在真值上满足 I 类或 II 类价值。
4. **所有场景都如实报告**，三种情况都是要用的素材：
   - FULL 更好：想象成功；
   - FULL 一样：想象没改变决定；
   - FULL 更差：想象偏乐观，要附最坏规则的结果。
   零准入的场景照样记录，这是"全部拒绝、回退"分支的素材。
5. **每个场景留证**：
   - 机器人相机 RGB-D；
   - 每个 Lux3D 任务的提交、完成、取回时刻，任务号、模式、实际上传的原图、原始 GLB；
   - 每份候选的准入指标、门槛和判定原因；
   - 预演矩阵（逐格结果）和关键格的轨迹；
   - 决策文件（走了哪条分支、为什么）；
   - 各臂真值执行的逐步 qpos、qvel、动作、关节目标、接触、阶段。

产出：

- `runs/v5/c2/<state>/...`
- `runs/v5/c2/core_table.csv`
- `docs/v5/C2_REPORT.md`
