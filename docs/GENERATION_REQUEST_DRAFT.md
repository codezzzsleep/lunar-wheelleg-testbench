# 一次性生成申请（草案 · 未授权）

> 本文件是**申请草案**，不构成本批授权。本批新增付费 create = 0；历史 500 积分授权不变；
> 实际扣费 unknown。未获批准前不执行任何生成。

## 1. 用途

1. **新留出集**：6–8 块真正的新几何石头（带棱角、破裂面、纹理），不是 R01 的缩放复制；
2. **两图纠错**：少量对象补第二视角图，用于检验"第二张图改变决策"是否真的会发生。

不为旧 R01/R02 追加精度补救生成。

## 2. 输入联系图（contact sheet）

每个对象一张联系图，包含：

| 字段 | 说明 |
| --- | --- |
| `object_id` | 与 `plans/holdout_protocol.json` 中的池编号一致 |
| `view_id` | `front` / `three_quarter_left` / `three_quarter_right` |
| `prompt_image_path` | 包内路径 |
| `prompt_image_sha256` | 完整 SHA256 |
| `model` / `model_version` | 供应商与版本 |
| `sample_index` | 同 prompt 的第几次采样，**固定 create_order** |
| `seed` | 若供应商支持固定种子 |

拟用输入：`assets/raw/*.glb` 中的独立几何（13 个）与 `runs/unseen/recovery_r3/stone_materials/R0*.stl`（4 个），
联系图由 `scripts/v7_contact_sheet.py`（待实现）生成并逐张写 SHA。

## 3. 任务规模与费用

| 项 | 值 |
| --- | --- |
| 每对象单图任务 | 2 次（约定分歧规则下补第 3 次） |
| 计划对象数 | 6–8 |
| 预计任务数 | 12–24（上限 24） |
| 两图纠错任务 | 3–4 |
| 总任务上限 | 28 |
| 单任务价格依据 | **待填**：需以供应商现行价目为准，本批未核实，不得臆造 |
| 费用上界 | **待填**：= 总任务上限 × 单任务价格 |
| 试点规则 | 先跑 2 个对象（≤6 任务），核对几何可用性与费用后，再放行其余 |

## 4. 放行规则

1. 用户明确批准本草案并给出单任务价格与费用上界后，方可执行；
2. 执行时固定 `create_order`，不按下载完成顺序或真值得分重新编号；
3. 首个候选作为**固定首候选基线**，失败不得偷偷换第二个；
4. 失败任务不自动重提；
5. 全部任务的对象、视角、模型、版本、sample_index、费用写入账本；
6. 实际扣费仍以外部对账为准，`unknown` 如实保留。
